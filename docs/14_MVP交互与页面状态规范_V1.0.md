# AI Wardrobe MVP 交互与页面状态规范 V1.0

- 文档状态：实现基线
- 适用范围：P0a、P0b、P0 Hardening

## 一、体验目标

MVP 的第一价值不是“生成一张漂亮图片”，而是让用户感到 AI 看懂了当前穿搭，并用最少改动给出可信改善。

体验必须满足：

- 3 秒内确认上传或任务已经开始。
- 文字诊断先行，不让用户为了图片结果停留在空白等待页。
- 用户离开页面不会中断任务。
- 失败必须解释下一步，并且明确不消耗使用次数。
- Before/After 必须说明具体修改，不制造“换了一个人”的错觉。
- 图片默认私有，分享必须经过用户主动确认。

## 二、视觉方向

视觉概念：个人衣橱编辑部（Personal Wardrobe Editorial）。

- 气质：克制、可信、温暖，有时装编辑感但不制造距离。
- 主色：纸张米白、墨黑、鼠尾草绿。
- 强调色：低饱和朱红，用于动作、进度和重点变化。
- 标题：中文衬线字体，形成“编辑点评”感。
- 正文：清晰中文无衬线字体，保障小屏阅读。
- 禁止使用泛滥的紫色 AI 渐变、过度玻璃拟态或游戏化霓虹。
- 动效只用于阶段切换、结果揭示和 Before/After，不能掩盖真实等待。

## 三、信息架构

MVP 一级入口：

- 今日：上传、诊断入口和最近结果。
- 任务中心：进行中、可重试和已完成任务。
- 我的：资料、额度、隐私、删除请求。

衣橱和穿搭完整 Tab 不在 MVP 开放。在进入 P0.5 前，不使用空壳 Tab 暗示不存在的能力。

## 四、核心页面与状态

### 4.1 今日页

目标：在 5 秒内让用户理解产品价值并开始上传。

必须展示：

- “一张照片，先看懂再改变”的价值主张。
- 上传穿搭照片主按钮。
- 默认私有、可删除的信任说明。
- 文字诊断速度、最小修改和失败不扣次数的承诺。
- 任务中心入口及进行中任务提示。

状态：

- `DEFAULT`：无进行中任务。
- `HAS_PENDING_JOB`：展示任务入口和当前阶段。
- `HAS_RECENT_RESULT`：展示最近一次诊断摘要。
- `OFFLINE`：保留最近摘要，禁用新上传并说明网络恢复后可继续。

### 4.2 图片选择与授权

用户动作：

1. 点击上传。
2. 查看照片要求。
3. 主动选择相册或拍摄。
4. 阅读并确认 AI 图片处理告知。
5. 进入上传。

照片要求：

- 优先正面或全身照。
- 穿搭主体清晰。
- 避免严重遮挡或多人混杂。
- 不要求用户授予全相册扫描权限。

不得在用户未操作时读取剪贴板、相册或其他图片。

### 4.3 上传页

状态机：

```text
LOCAL_DRAFT
→ REQUESTING_TICKET
→ UPLOADING
→ VERIFYING
→ COMPLETED
  / INTERRUPTED
  / REJECTED
```

状态要求：

- `LOCAL_DRAFT`：保存本地文件引用和创建时间。
- `UPLOADING`：展示真实上传百分比。
- `INTERRUPTED`：保留草稿，提供“继续上传”。
- `REJECTED`：解释文件类型、大小或图片尺寸问题。
- `COMPLETED`：自动进入场景选择，不要求重复点击。

P0 不展示虚假的分片断点续传。网络中断后是保留草稿并重新上传。

### 4.4 场景选择

MVP 场景：

- 日常休闲。
- 上学。
- 通勤。
- 面试。
- 约会。
- 聚会。
- 旅行。
- 其他。

默认不替用户推断敏感场景。每次只选一个主要 Occasion。

### 4.5 Job 进度页

用户可见阶段：

| 后端状态 | 用户文案 | 进度表现 |
|:---|:---|:---|
| PENDING | 正在准备 | 8% |
| QUEUED | 已进入分析队列 | 18% |
| PROCESSING | AI 正在理解你的穿搭 | 52% |
| QUALITY_CHECKING | 正在检查结果 | 82% |
| COMPLETED | 结果已准备好 | 100% |
| FAILED_RETRYABLE | 这次没有成功，可以重试 | 不展示伪进度 |
| FAILED_FINAL | 这次结果没有生成成功 | 不展示伪进度 |
| TIMED_OUT | 任务仍在后台处理 | 转入任务中心 |
| CANCELLED | 任务已取消 | 终态 |

规则：

- 页面可以关闭。
- `jobId` 写入 `pendingJobs`。
- 下次启动自动查询未完成任务。
- 轮询退避，不使用固定高频请求。
- 前端轮询上限不等于取消后端任务。

### 4.6 诊断结果页

展示顺序：

1. 总体评分及场景。
2. 一句总结。
3. 具体优点，最多三项。
4. Primary Issue。
5. 可执行建议。
6. “看看优化后是什么样”主按钮。

禁止：

- 空泛夸奖。
- 对身体、性别、肤色或身份作无依据推断。
- 使用羞辱性表达。
- 把分数包装成审美绝对标准。
- 在诊断阶段直接推荐购买商品。

结果必须标注“AI 建议仅供参考”，并允许用户反馈不准确。

### 4.7 Optimization 等待页

必须说明：

- 采用 Minimal Change。
- 优先调整穿法，其次替换一件，最多替换两件。
- 用户可以离开页面。
- 失败不会消耗使用次数。

文字诊断保持可见，不能重新退回空白 Loading。

### 4.8 Before/After 页

必须展示：

- 相同画幅中的 Before 与 After。
- 清晰的拖动或切换对比。
- “只改了什么”列表。
- Change Budget Level。
- 保存和分享按钮。
- 结果问题反馈入口。

如果 Critic 判定身份、保留衣物或背景发生不可接受变化，不得向用户展示该结果。

### 4.9 分享确认页

分享前必须：

- 生成独立 Share Asset。
- 默认移除私人元数据和永久私有 URL。
- 展示将要分享的最终画面。
- 允许用户取消。
- 标识 AI 生成或 AI 编辑内容。

用户可以选择是否展示评分。默认不在分享图中展示敏感资料。

### 4.10 分享落地与 A/B Vote

好友可见：

- Before/After。
- 简短的修改说明。
- “你更喜欢哪一个”投票。
- 继续体验入口。

好友不得通过分享页访问：

- 原始私人照片 URL。
- 用户其他诊断记录。
- 用户身份详情。
- 任务、额度或隐私设置。

### 4.11 任务中心

分组：

- 进行中。
- 可以重试。
- 最近完成。

每个任务展示类型、创建时间、当前阶段和下一步。最终失败任务提供重新创建入口，不复用已失效的 Provider 调用。

### 4.12 隐私与删除

必须提供：

- 图片列表与单张删除。
- 账号删除请求。
- 删除任务状态。
- 图片和 AI 处理说明。
- 当前隐私政策与同意版本。

删除请求提交后必须明确其处理状态，不得仅显示“提交成功”后失去追踪。

## 五、错误与降级文案

| 场景 | 用户文案 | 操作 |
|:---|:---|:---|
| 网络中断 | 网络断开了，照片草稿已保留。 | 继续上传 |
| 图片不合格 | 没有识别到完整穿搭，请换一张正面或全身照片。 | 重新选择 |
| AI 临时失败 | 这次生成没有成功，我们没有消耗你的次数。 | 重试 |
| 最终失败 | AI 今天状态不太好，这次结果没有生成成功。 | 重新开始 |
| 处理超时 | 任务仍在后台处理，你可以先离开。 | 查看任务中心 |
| 达到额度 | 今天的免费次数已用完，明天可以继续。 | 查看额度 |
| 请求过快 | 操作有点快，请稍后再试。 | 倒计时后重试 |
| 分享失效 | 这份分享已经失效。 | 开始自己的体验 |
| 删除处理中 | 正在删除你的数据，完成后会在这里更新。 | 查看状态 |

内部错误码、Provider 名称、COS 路径和 Trace 细节不得进入用户文案。

## 六、无障碍与低端设备

- 正文不小于 24rpx，辅助文字不小于 20rpx。
- 文本与背景保持足够对比度。
- 不能只依赖颜色表达成功、失败或进度。
- 动效尊重系统减少动态效果设置。
- 点击区域不小于 88rpx × 88rpx。
- Before/After 必须提供按钮切换，不能只支持拖动手势。
- 低端设备不加载不必要的原图和多层实时滤镜。

## 七、验收方式

每个页面必须验证：

- 正常路径。
- 空状态。
- 加载状态。
- 弱网或离线。
- 可重试失败。
- 最终失败。
- 页面退出与恢复。
- 跨用户资源隔离。
- 低端安卓真机。

页面实现与本规范不一致时，应先更新规范并获得产品确认，不得在代码中形成未记录的新交互。
