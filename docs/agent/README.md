# AI Agent 任务落地清单

本目录服务于仓库内的编码 Agent。根目录 `AGENTS.md` 是最高优先级协作规范，
`CLAUDE.md` 是快速入口，本文件只补充可操作的交付清单。

## 1. 接收任务

- 用一句话写清用户要获得的结果，而不是要修改的文件。
- 标注 Phase、Epic、Milestone 或 Release Gate。
- 列出成功标准、失败路径、安全要求和明确不做项。
- 检查当前分支、远程仓库和未提交改动。
- 不确定的业务语义必须回到 PRD、ADR、TDD、DDD 或 API 文档。

## 2. 加载上下文

- 产品范围：`docs/01_产品需求文档_PRD_V1.0.md`。
- 技术与模块边界：`docs/02_技术方案设计_TDD_V1.0.md`。
- 数据语义：`docs/03_数据架构与数据库设计_DDD_V1.0.md`。
- API 契约：`docs/04_API与外部集成方案_V1.0.md`。
- NFR 与 SLO：`docs/11_非功能性需求NFR与SLO_V1.0.md`。
- 当前实现与优化：`docs/13`、`docs/19`。
- 验收、封测和发布：`docs/16`、`docs/17`。
- 只加载与当前任务直接相关的章节，避免无边界扩张上下文。

## 3. 设计变更

- 从用户动作到 API、事务、Outbox、Worker、Provider 和结果恢复画出数据路径。
- 明确业务真相源、本地缓存、幂等键、所有权和事务边界。
- 对外部失败、超时、重试、取消、重复请求和迟到结果逐一给出语义。
- AI 变更记录 Provider、Model、Prompt、Schema、成本和质量阈值。
- 新增框架、存储、消息系统或跨模块依赖前先提出 ADR。

## 4. 实现约束

- 后端保持 Public Service → Domain → Infrastructure 单向依赖。
- 前端区分 Server State 与 UI State，后台任务必须可离页恢复。
- 图片继续直传私有 COS，分享只使用独立派生资产。
- 写操作必须有鉴权、所有权、幂等、限流和安全失败文案。
- 数据删除覆盖原图、派生图、数据库、缓存和 Provider 临时数据。
- 不得记录敏感用户标识、访问 Token、私有 URL 或图片正文。
- 工程目录最多 8 个直接文件，源码文件最多 800 行。

## 5. 验证矩阵

- Python：Ruff、格式检查、严格 Mypy、单元与契约测试。
- 数据库：真实 PostgreSQL/Redis 集成测试、Alembic 升级和模型漂移。
- 小程序：ESLint、`vue-tsc`、Vitest 和微信生产构建。
- 安全：Python 与 pnpm 生产依赖审计、日志脱敏和跨用户隔离。
- AI：Golden Dataset、上一版本对比、人工抽样和成本基线。
- 发布：Staging E2E、真实 COS/OpenAI/微信、真机矩阵和回滚演练。
- Mock 只能证明代码分支，不能替代外部系统或性能 Gate 的真实证据。

## 6. 提交与交接

1. 每个独立修复或重构单独提交。
2. 提交信息用中文说明问题、处理原因和验证范围。
3. 提交后立即推送 `develop`，不在本地积压。
4. 同一任务内同步更新契约、运行手册和进度证据。
5. 交接时列出提交、CI 链接、测试数量、未执行项和阻塞条件。

## 7. 外部阻塞

- 缺少 Staging、COS、微信或 OpenAI 凭据时，继续完成本地安全验证。
- 缺少授权样本时不得伪造 Eval 结论，也不得降低质量阈值。
- 需要发送消息、发布内容或改变生产状态时，先取得负责人明确授权。
- 阻塞不等于完成；在 `docs/13` 和 `docs/19` 中保留 NO-GO 条件。
