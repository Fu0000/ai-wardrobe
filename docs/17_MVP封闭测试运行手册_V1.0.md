# AI Wardrobe MVP 封闭测试运行手册 V1.0

## 一、目标与边界

首轮仅邀请 30～50 名明确知情并自愿参与的测试用户，验证“真实穿搭照片 → AI 诊断 → 最小改变优化 → 微信分享与投票”的核心假设。封测不是公开发布，不承诺医疗、身体评价、购买建议或专业形象咨询。

硬性边界：

- 只处理测试者本人有权上传的照片，不得包含未同意的第三人。
- AI 结果是风格建议而非客观事实；不得基于身材、年龄、种族等作贬损判断。
- 原图默认私有；公开分享只能使用独立派生图并明确标注 AI 编辑。
- 用户可单图删除、撤回 AI 授权或删除账号。
- Blocker/Critical、隐私、安全、数据丢失或成本失控时立即暂停新增邀请。

## 二、测试用户准入

产品负责人维护受控名单，不得提交到 Git 仓库。每名测试者记录：

| 字段 | 要求 |
|:---|:---|
| 测试者编号 | 使用内部随机编号，不在报告中写姓名/OpenID |
| 联系渠道 | 存放在受控通讯录，仅产品/On-call 可见 |
| 设备 | iOS/Android、机型、系统和微信版本 |
| 授权状态 | 已阅读封测说明、照片权利和 AI 处理说明 |
| 测试批次 | Wave 1/2/3 |
| 开始/退出时间 | 可追踪且可随时退出 |
| 数据删除请求 | 请求时间、状态、完成时间，不复制照片 |

招募信息必须明确：测试目的、会处理的数据、AI 局限、数据可删除、反馈渠道、可能产生的等待/失败、退出方式和联系人。不得以默认勾选代替同意。

## 三、分批开放

| 批次 | 人数 | 最短观察 | 放量条件 |
|:---|---:|:---|:---|
| Wave 0 | 3～5 名内部测试者 | 1 个完整测试日 | 全部 Release Gate 已签署，主路径逐人完成 |
| Wave 1 | 累计 10 名 | 24 小时 | Blocker/Critical=0，成功率/延迟/成本无异常 |
| Wave 2 | 累计 25 名 | 48 小时 | 删除、分享、告警和反馈闭环均有真实记录 |
| Wave 3 | 累计 30～50 名 | 至少 7 天 | 每日复盘稳定，无硬停止条件 |

每次放量由产品、QA、技术和 On-call 共同记录时间、人数、版本 SHA 和决策。不得跳过批次或一次性邀请全部用户。

## 四、测试者任务

每名测试者至少完成：

1. 登录并阅读 AI 处理说明。
2. 分别使用相册和拍照上传本人穿搭。
3. 选择至少两个真实场景并查看诊断。
4. 生成一次 Minimal Change Optimization，核对身份、衣服和意外变化。
5. 退出小程序后重新进入，确认任务恢复。
6. 生成分享卡并由另一微信账号打开、投票。
7. 提交一条应用内反馈。
8. 至少由测试样本中的指定人员执行单图删除；另由专用测试账号执行账号删除。

禁止引导用户故意上传敏感证件、裸露内容、未成年人照片或无授权第三人照片。

## 五、反馈与 Bug 分诊

应用内反馈保存分类、可选评分、正文、页面、最小设备信息，以及用户主动关联且通过 Ownership 校验的 Job/Trace；不保存照片、签名 URL、Access Token 或微信 OpenID。

每日两次由 QA 在受控环境查询 `beta_feedback` 中的 `NEW` 记录，创建去敏 Bug/产品条目后改为 `TRIAGED`。仓库 Issue、群消息和发布报告不得复制用户原文中的个人信息。

分级遵循《MVP 验收与发布清单》：

- Blocker：立即通知 On-call，暂停邀请和相关功能。
- Critical：2 小时内定责，发布前清零。
- Major：1 个工作日内确定 Owner、截止日和绕行方案。
- Minor：进入 Backlog，不打断测试者正常旅程。

需要联系测试者补充信息时，只询问复现步骤、时间、测试者编号、Request ID/Trace ID；不得要求其在群中发送原图或 Token。

## 六、每日观测与复盘

每天固定记录：

- 登录、上传、Diagnosis、Optimization、Share、Open、Vote、Continue 转化；
- Diagnosis/Optimization 成功率、P50/P90/P95、Fallback 和最终失败；
- Critic First-pass、人工抽样 Fidelity 和输入质量拒绝；
- API 5xx/P95、DB/Redis、Outbox Pending Age、队列等待和 Worker 重试；
- Provider 错误、单位成本、当日/累计预算；
- 单图/账号删除成功率与完成时间；
- 新增 Bug、严重度、Owner、老化时间；
- 测试人数、活跃人数、退出和删除请求。

复盘只使用聚合指标和内部测试者编号。任何截图先确认不含照片、用户标识、Token、签名 URL、Prompt 全文或 Secret。

| AI/Provider | 待填写 | 待填写 | 待填写 | 待填写 |
| Miniapp/WeChat | 待填写 | 待填写 | 待填写 | 待填写 |
| Product/Tester Comms | 待填写 | 待填写 | 待填写 | 待填写 |

事件流程：

1. 告警或反馈进入后确认影响范围，记录开始时间、环境、SHA 和 Incident ID。
2. 先止损：暂停邀请、将 AI Canary 设为 0%、关闭受影响入口或应用回滚。
3. 不回滚数据库；迁移问题使用兼容旧/新 Schema 的应用或前向修复。
4. 通过 Trace ID、Job ID 和聚合指标定位，日志不得加入新的敏感字段。
5. 每 30 分钟更新一次内部状态；影响测试者时由产品发送去技术化通知。
6. 恢复后执行 Readiness、核心冒烟、数据一致性、额度和删除检查。
7. 24 小时内完成简报；Blocker/Critical 在 3 个工作日内完成复盘和行动项。

## 八、硬停止条件

任一条件触发即停止新增邀请，必要时暂停服务：

- 跨用户访问、原图公开、Token/Secret/签名 URL 泄露；
- 单图或账号删除最终失败，或完成后数据仍可访问；
- 数据丢失、Job 丢失、重复扣额度；
- 未通过 Critic 的高风险优化图被展示或分享；
- API 5xx 持续 >2%，Diagnosis 成功率 <95%，P95 ≥30 秒；
- Provider/队列错误持续增长且无可控恢复时间；
- 单位成本超过 Ceiling 或累计预算达到 80%；
- Blocker 或无 Owner 的 Critical；
- On-call、告警或回滚能力不可用。

恢复邀请必须由产品、QA、技术和 On-call 共同确认，不能由单一开发者口头决定。

## 九、测试者通知模板

开始：

> 你正在参与 AI Wardrobe 封闭测试。请只上传你有权使用的本人照片。AI 结果是风格建议，不代表客观评价。原图默认私有，你可以删除照片、撤回授权或删除账号。遇到问题请使用“个人设置 → 内测反馈”，不要在群里发送原图或登录信息。

故障：

> 当前 AI 处理出现异常，我们已暂停新的任务。你的原图不会因此公开；已失败任务不会消耗免费额度。请暂时不要重复上传，恢复后会在本渠道通知。

隐私事件应使用经 Incident Commander 和产品负责人审核的专项模板，不得在未确认事实前猜测影响范围。

结束：

> 本轮封闭测试已结束。感谢你的参与。你仍可在应用内删除照片或账号；如希望我们协助确认删除状态，请提供测试者编号，不要发送原图、Token 或微信身份信息。
