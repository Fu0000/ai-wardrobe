Unit、Integration、Contract、AI Eval、Visual QA、E2E、Performance、Security、Privacy。

## 二、AI Eval

Garment Detection：遮挡、弱光、复杂背景。
Entity Resolution：同衣不同照片、相似黑色基础款。
Display Asset：Logo、Color、Structure、Anchor。
Try-On：Identity、Garment Fidelity、Unexpected Change。

## 三、性能

## 四、发布
Feature Branch → PR → CI → Staging → Product QA → AI Regression → Migration Review → Canary → Production。

## 五、数据库迁移
只向前 Migration；禁止生产手工改表；破坏性字段分两阶段下线。

## 六、AI 灰度
Old Model → Shadow Eval → 10% Canary → 50% → 100%。
全程记录 model_version / prompt_version。

### Model Release Guardrail
灰度阶段综合监控 Quality、Error Rate、Latency、Cost。
任一触发回滚条件时 Pause Rollout：
- Quality 下降 > 10%
- Error Rate 上涨 > 5pp
- P95 Latency 上涨 > 50%
- Unit Cost 上涨 > 30%

回滚时：当前处理中的 Job 按创建时的 model_policy_snapshot 继续执行，新 Job 全部路由到旧模型版本。运维手动确认后完成回滚，回滚操作记录到 ADR。

## 七、运维指标

## 十、数据库备份与恢复

## 十一、日志采集与查询
### 日志方案
P0 代码基线：Docker stdout 结构化日志 + OpenTelemetry Trace，按 TraceID 串联。
Staging Terraform 已声明保留 15 天、KMS 加密且启用销毁保护的腾讯云 CLS TKE
Audit/Event 和公网 CLB Access Topic；应用 stdout/OTLP 接入、真实云资源创建与查询证据仍待 INF-02
Staging 执行。Production 需在独立账号和状态中建立同等或更严格合同。

### 标准字段
timestamp、level、service、environment、trace_id、request_id、user_id_hash、job_id、endpoint、latency_ms、status_code、error_code。
注意：日志不要直接存敏感原始 user_id、照片 URL、Prompt 全文。

### AI 调用日志
provider、model、prompt_version、schema_version、input_token、output_token、estimated_cost、latency。
Prompt 正文默认不进入普通日志，需要 Debug 时单独受控。

## 十二、COS 存储成本监控
监控指标：total_storage_bytes、monthly_growth、avg_storage_per_active_user、expired_asset_bytes、orphan_asset_count。
核心关注 Cost per Active User 和 Orphan Asset Rate。
建立 AssetGCJob 定期清理 EXPIRED 的 Scene Render 和被替换的 Display Asset。
P1 后考虑 COS 生命周期规则：长期未访问资产转低频存储。
